# GadgetBoy POS v0.6.92

- Work-order and sales printouts now wait for a successfully rendered QR code before printing, including retries for temporary QR service delays.
- If a QR cannot be created, the receipt opens with the error instead of silently printing without the QR.
- Closed work orders and resolved client replies now stay removed from Command Center while synchronization completes.
- Close and resolve actions now report persistence failures rather than appearing successful and then returning.
- Diagnosis, testing, approval, parts, repair-complete, not-repairable, picked-up, and closed updates now route directly to the matching Command Center section.
- Tickets closed or picked up from the QR/update window stay removed from active lists and Today’s Repair Queue while synchronization completes.
