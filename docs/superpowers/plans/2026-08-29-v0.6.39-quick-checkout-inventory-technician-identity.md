# v0.6.39 Quick Checkout, Inventory Navigation, and Technician Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.6.39 with successful Quick Checkout auto-close, inventory parent/variant context actions and device-priority search, synchronized technician profile icons, and avatar-driven Daily Look tasks.

**Architecture:** Extend existing state and persistence paths rather than creating parallel systems. Put icon catalog/rendering and inventory search/menu logic in focused helpers, then consume them from existing desktop/mobile-shared React components; persist only a nullable icon identifier on `staff_profiles` and resolve it live when rendering tickets.

**Tech Stack:** React 18, TypeScript 5.9, Electron 29, Vite 5, Tailwind CSS, Node assertion-based regression scripts, Supabase/Postgres, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-29-v0.6.39-quick-checkout-inventory-technician-identity-design.md`

## Global Constraints

- Preserve unrelated dirty workspace files and stage only files named by each task.
- Profile icons are application-only and must never be added to receipt, work-order, sale, or consultation print HTML/models.
- Desktop right-click and mobile long-press must expose equivalent inventory actions through the existing context-menu bridge.
- Persist a fixed catalog identifier only; never persist SVG markup or an external image URL.
- The `staff_profiles` schema change is additive and nullable; do not broaden RLS or create a new table.
- Quick Checkout closes only after its existing successful completion path finishes.
- Use v0.6.39 only if repository/tag inspection still shows v0.6.38 as latest.
