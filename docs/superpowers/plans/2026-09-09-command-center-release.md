# Command Center Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the passive desktop main record list with the responsive GadgetBoy Command Center while preserving every existing production workflow and publishing the next Windows release.

**Architecture:** Add a pure operational-derivation module that converts existing customers, work orders, sales, calendar entries, technicians, and purchasing records into Command Center metrics and queues. Render that model in a focused React component embedded in the existing `App` shell; the existing work-order, sale, consultation, Admin, quote, calendar, notification, client, and checkout components remain authoritative and are opened through the existing modal/IPC routes. Keep All Invoices as the existing table implementation and use CSS media queries for desktop/tablet reflow.

**Tech Stack:** React 18, TypeScript, Electron IPC/preload APIs, Vite, Tailwind plus existing project CSS, Node test scripts, electron-builder/NSIS.

**Spec:** `.superpowers/brainstorm/84-1788804069/content/pos-interactive-mobile-v51.html`

## Global Constraints

- Do not replace or duplicate existing Admin, work-order, sale, consultation, client, checkout, quote, calendar, notification, reporting, or technician business logic.
- Command Center data must be derived from persisted POS records; no preview/sample customer data may ship.
- Waiting-on-parts repairs remain out of the active repair route until a part is delivered or its ETA is due.
- All Invoices retains the existing production tables, pagination, double-click, and context actions.
- Desktop and tablet layouts must adapt automatically to available width.
- New release version must advance from `0.6.62` and use the existing updater/release feed.
